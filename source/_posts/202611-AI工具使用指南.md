## 一、四个工具，各管一段

| 工具 | 官网 | 我拿它干什么 | 模型从哪来 |
|---|---|---|---|
| Hermes（更） | [hermes-agent.nousresearch.com](https://hermes-agent.nousresearch.com/) | 总管家：记事、定时任务、管服务器、写文档 | 我自己的中转站 |
| Codex | [developers.openai.com/codex](https://developers.openai.com/codex/) | 在仓库里改代码、修 bug、跑测试 | ChatGPT 订阅额度 |
| Claude Code | [claude.com/product/claude-code](https://www.claude.com/product/claude-code) | 读长文档、拆需求、做分析 | 中转站的 Claude 系列 |
| Pi | [pi.dev](https://pi.dev/) | 随手一问、跑个小脚本 | 中转站 |

## 二、Hermes：总管家

![Hermes 官网](/images/261111-30.webp)

它不是「一个聊天框」，而是常驻在我电脑上的 agent：微信和飞书都能找到它，能自己跑定时任务、读写文件、连服务器、调别的 agent。

**怎么装**：官网有各平台的安装说明，装完用 `hermes` 启动，第一次会让你配模型和消息入口。我这边是接自己的中转站，不走官方额度。

**我常用的命令**：

```bash
hermes                     # 启动交互
hermes tools list          # 看当前启用了哪些工具
hermes cron list           # 看定时任务
hermes mcp list            # 看挂了哪些 MCP 服务
hermes memory status       # 看记忆库状态
hermes plugins list        # 看插件
```

**独有的地方**：它的定时任务、记忆和「分身」是绑在一起的——我可以让它每天早上自动发日报、盯着服务器到期日、把每周的复盘写进文档，不需要我张嘴。

## 三、Codex：改代码最顺

![OpenAI 文档里的 Codex 界面](/images/261111-31.webp)

绑的是 ChatGPT 订阅额度，所以不按 token 单独付费。

**安装**：官方文档里给的是 npm 全局安装，装完 `codex login` 走一次浏览器授权。

**常用命令**：

```bash
codex                      # 打开交互界面
codex exec "把测试补全"     # 无头执行一条任务，适合脚本里调
codex login                # 登录 / 刷新授权
codex --version            # 看版本
```

配置在 `~/.codex/config.toml`，模型、审批策略都在里面改。

**适合什么**：给它一个项目路径 + 一个明确目标，它会自己读文件、跑命令、看报错、接着改。改完我只看 diff。

## 四、Claude Code：读得最细

![Claude Code 官网](/images/261111-32.webp)

Claude 在长文本上的耐心确实好：一篇几十页的论文、一份很长的需求文档，让它读完再拆，比别的工具稳。

**安装**：官网给的是 npm 安装 + `claude` 启动，第一次要浏览器登录。

**常用命令**：

```bash
claude                              # 交互
claude -p "总结这篇论文的方法"       # 无头模式，输出到终端
claude --continue                   # 接着上一次会话
claude --resume                     # 从历史会话里挑一个继续
claude --model sonnet               # 临时换模型
claude --dangerously-skip-permissions   # 跳过逐步确认（只在自己可控目录用）
claude mcp add <名字> <命令>         # 挂 MCP 服务
```

**会话里的斜杠命令**：

```text
/init       给当前项目生成 CLAUDE.md
/compact    压缩上下文，长会话续命
/clear      清空当前会话
/cost       看这次会话花了多少
```

**我踩过的配置坑**：走中转站时 `base_url` 不能带 `/v1`，模型名不能带 `[1M]` 这类后缀，写错就是 404。

## 五、Pi：最快的那一个

![Pi 官网](/images/261111-33.webp)

Pi 比上面两个都轻，启动快，适合「我就问一句」或者验证一个小脚本。

**常用命令**：

```bash
pi                      # 交互
pi -p "解释这段报错"     # 一次性提问
pi --version            # 看版本
```

配置在 `~/.pi/agent/models.json`，模型清单是白名单制——没加进去的模型不能选。

## 六、Agent 通用命令（这几个都适用）

不管是哪一个，下面这些套路是共通的：

**开关与版本**

```bash
<工具名> --version      # 确认装的是哪个版本
<工具名> --help         # 看当前版本支持哪些参数
```

**无头模式（给脚本/定时任务用）**

```bash
codex exec "任务"
claude -p "任务"
pi -p "任务"
```

**续接会话**

```bash
claude --continue
claude --resume
```

**指定模型**

```bash
claude --model sonnet
codex --model <模型名>
```

**危险开关（慎用）**

```bash
claude --dangerously-skip-permissions
```

跳过每一步确认，快是快，但它会真的删文件、真的推代码——只在自己有备份的目录里用。

**会话内文档**

在 Claude Code / Codex 里跑一次 `/init`，它会把项目结构、构建命令、约定写成一个 markdown，后面每次进来都先读这个，少走弯路。

## 七、怎么选

- 要记事、要自动化、要它替我盯着东西 → **Hermes**
- 要改代码、要它自己迭代 → **Codex**
- 要读长文、做分析、拆需求 → **Claude Code**
- 只问一句、随手验证 → **Pi**

复杂任务就让它们接力：Hermes 拆活 → Codex 写 → Claude 审 → 我把结果归档。
